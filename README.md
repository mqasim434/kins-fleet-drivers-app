# KINS Fleet Chauffeur (Drivers App)

Flutter app for KINS Logistics drivers. It uses the same Firebase project as the fleet dashboard: driver accounts, planning shifts, buses, photos, and damage reports. Drivers do not re-enter that data.

- Login with the driver account created in the dashboard.
- Today and upcoming shifts, including the assigned bus.
- Photos from the camera for inspection, vehicle condition, damage, or other checks. Photos are stored on the bus and show up for the fleet manager.
- A damage photo also creates a damage report in Schades.

## Prerequisites

- Flutter 3.x (stable), Dart 3.x
- Firebase CLI: `npx -y firebase-tools@latest login`
- FlutterFire CLI: `dart pub global activate flutterfire_cli`

## Environment variables (ImageKit)

Copy `.env.json.example` to `.env.json` (gitignored) and fill in values:

```bash
flutter run --dart-define-from-file=.env.json
```

Release builds **must** pass the same file or ImageKit uploads will fail.

## Run


## Build (Play Store)

```bash
flutter build apk --release --dart-define-from-file=.env.json
flutter build appbundle --release --dart-define-from-file=.env.json
```

Full Play release steps: [docs/PLAY_RELEASE.md](docs/PLAY_RELEASE.md).

### Google Play (Android)

1. Create an upload keystore (once) and `android/key.properties` (see `android/key.properties.example`; both are gitignored).
2. Build the App Bundle with ImageKit defines (command above).
3. In [Play Console](https://play.google.com/console): app package **`com.kins.logistics.driver`**, complete **Data safety** (account, location for clock-in, photos), **content rating**, upload the `.aab` to Internal testing, then Production.
4. **Adaptive icon** and **predictive back** are configured in `AndroidManifest.xml` / `mipmap-anydpi-v26`.

### App Store (iOS)

1. Bundle ID **`nl.kins.logistics.driver`** — register in Apple Developer → Identifiers.
2. Open `ios/Runner.xcworkspace` in Xcode: set **Team**, **Signing & Capabilities**, and bump **Version / Build** to match `pubspec.yaml` (`version: x.y.z+build`).
3. Archive: **Product → Archive** → **Distribute App** → App Store Connect.
4. In App Store Connect: privacy labels, **encryption** (app sets `ITSAppUsesNonExemptEncryption = false` for standard HTTPS only), and review notes (driver login only, no public signup).
5. Store display name: **KINS Chauffeur** (`CFBundleDisplayName`).

### Store assets

Marketing icons: `assets/logo/playstore.png` (512×512) and `assets/logo/appstore.png` (1024×1024). In-app launcher icons are under `android/app/src/main/res/` and `ios/Runner/Assets.xcassets/AppIcon.appiconset/`.

## Accounts

Driver accounts are created on the web dashboard — there is no signup in this app.

A login needs `users/{uid}` with `role: driver`, `status: active`, and `driverId` pointing at `drivers/{driverId}`.

## Firestore rules prerequisite

Driver photo uploads need `busPhotos` **create** rules on **`kins-logistics`**. From the `kins-fleet-dashboard` repo:

```bash
npx -y firebase-tools@latest deploy --only firestore:rules --project kins-logistics
```

### Billing / quotas

Prefer the **Blaze** plan for production. On Spark, Firestore is capped at **50K reads / 20K writes per day**; when exhausted, photo metadata saves fail (ImageKit may still succeed). Upgrade: [Usage & billing](https://console.firebase.google.com/project/kins-logistics/usage/details).
